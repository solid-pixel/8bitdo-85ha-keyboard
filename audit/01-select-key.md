1. Select a physical key — usable, visually crowded.
Evidence: 01-select-key.png, live screenshot with Right Alt selected.
Strength: recognizable keyboard geometry and saved mappings visible on key faces; selected key is also named in the editor.
UX: repeated instructions compete with the editing task; backup/reload controls sit beside the large title; physical key and destination are far apart; unexplained dots require a legend; implementation details about 19 entries read like a persistent error.
Accessibility risk: small secondary legends and pale helper text need contrast review; selected state is largely color-based on the board, though the editor repeats the key name. Screen-reader behavior and contrast compliance have not been tested.
Recommendation: compact header, a clear keyboard surface, explicit changed/macro styling, and one focused editor panel with a readable change summary.
